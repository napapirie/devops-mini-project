# Ответы к пересдаче по DevOps

## Задание 1. Основы DevOps

### 1. Теория

#### 1. DevOps
DevOps — это подход к разработке и эксплуатации программного обеспечения, который объединяет работу разработчиков и специалистов, отвечающих за инфраструктуру и запуск приложения. Его цель — сделать выпуск изменений более быстрым, предсказуемым и безопасным. В DevOps большое внимание уделяется автоматизации: сборке, тестированию, развертыванию и мониторингу. Также важны единые процессы и ответственность команды за приложение на всем его жизненном цикле. Благодаря DevOps уменьшается количество ситуаций, когда программа работает у разработчика, но не работает на сервере.

#### 2. Git, commit и branch
Git — это распределенная система контроля версий, которая хранит историю изменений проекта и позволяет нескольким разработчикам работать с одним кодом. Commit — это сохраненная точка в истории Git, в которой фиксируется определенное состояние файлов проекта и комментарий к изменению. Commit можно представить как снимок проекта в конкретный момент времени. Branch, или ветка, — это отдельная линия разработки, в которой можно делать изменения независимо от основной версии проекта. После проверки изменения из ветки обычно объединяют с основной веткой, например main.

#### 3. CI/CD
CI/CD — это набор практик автоматизации проверки и доставки программного обеспечения. CI расшифровывается как Continuous Integration — непрерывная интеграция: после изменений кода система автоматически собирает проект, проверяет его и запускает тесты. CD может означать Continuous Delivery или Continuous Deployment — непрерывную доставку или автоматическое развертывание. CI/CD помогает быстрее находить ошибки и уменьшает количество ручных операций. Обычно CI/CD реализуется в виде pipeline, состоящего из последовательных шагов.

#### 4. Docker: образ и контейнер
Docker — это платформа контейнеризации, которая позволяет упаковать приложение вместе с необходимым окружением и запускать его одинаково на разных компьютерах и серверах. Docker image, или образ, — это неизменяемый шаблон, из которого создаются контейнеры. В образе описываются операционная среда, файлы приложения и команды запуска. Docker container, или контейнер, — это уже запущенный экземпляр образа. Один образ можно использовать для запуска нескольких одинаковых контейнеров.

### 2. Связи и логика
Разработчик пишет код на своем компьютере и сохраняет изменения с помощью Git. Git хранит историю commit-ов и позволяет работать в разных branch-ах. Затем код отправляется в удаленный репозиторий GitHub, где он доступен команде и системам автоматизации. После push в GitHub может автоматически запускаться CI/CD pipeline через GitHub Actions. Pipeline получает исходный код, устанавливает нужную версию Python и зависимости, а затем выполняет проверки, например проверку синтаксиса. После успешной проверки приложение можно собрать в Docker image. Из Docker image запускается Docker container, поэтому приложение получает одинаковое окружение и на компьютере разработчика, и на сервере. Сервер чаще всего работает под Linux, потому что Linux широко используется для серверной инфраструктуры и хорошо поддерживает Docker и средства автоматизации. Сам Linux-сервер может находиться локально или в облаке. Облако предоставляет виртуальные серверы, сети и хранилища, на которых можно развернуть приложение. Таким образом, последовательность выглядит так: разработка кода → Git → GitHub → CI/CD → Docker image → Docker container → Linux-сервер → облачная инфраструктура.

### 3. Практическая ситуация
1. Разработчик загружает исходный код веб-приложения в Git-репозиторий и фиксирует изменения через commit.
2. Репозиторий размещается на GitHub, чтобы код можно было получить на сервере и подключить автоматизацию.
3. Я проверяю исходный код и выясняю, какие версии Python и зависимости использовались на компьютере разработчика.
4. Я создаю или проверяю `requirements.txt`, чтобы зависимости проекта были явно зафиксированы.
5. Я создаю `Dockerfile`, в котором указываю базовый образ, рабочую директорию, копирование проекта и команду запуска.
6. Локально выполняю `docker build -t devops-app .`, чтобы собрать Docker image.
7. Запускаю контейнер командой `docker run -p 5000:5000 devops-app` и проверяю приложение через `http://localhost:5000`.
8. Если приложение работает в контейнере локально, это означает, что его окружение теперь воспроизводимо и меньше зависит от настроек компьютера разработчика.
9. На GitHub настраиваю CI/CD pipeline через файл `.github/workflows/ci.yml`.
10. При каждом push pipeline запускается на Linux-окружении `ubuntu-latest`, получает код, устанавливает Python и зависимости и выполняет проверку синтаксиса.
11. После успешной CI-проверки Docker image можно передать или собрать на Linux-сервере.
12. На сервере запускается тот же Docker container с тем же образом и пробросом нужного порта, после чего сервис проверяется по адресу сервера.

## Блок 2. Короткие ответы на устные вопросы

1. **Что такое DevOps?** DevOps — это подход, объединяющий разработку и эксплуатацию. Он решает проблему разрыва между теми, кто пишет приложение, и теми, кто запускает и поддерживает его.
2. **Что такое Git? Commit и branch?** Git хранит историю изменений. Commit — зафиксированное состояние проекта, branch — отдельная линия разработки.
3. **GitHub и Git — в чем разница?** Git работает локально как система контроля версий, а GitHub — онлайн-сервис для хранения Git-репозиториев и совместной работы.
4. **Что такое Linux и почему он популярен на серверах?** Linux — семейство операционных систем с открытым исходным кодом. Он стабилен, хорошо автоматизируется и широко используется в серверной инфраструктуре.
5. **Микросервисы и монолит?** Монолит — одно большое приложение, а микросервисная архитектура делит систему на небольшие независимые сервисы.
6. **Что такое Cloud Computing?** Это получение вычислительных ресурсов через облачного провайдера. IaaS предоставляет инфраструктуру, PaaS — платформу для запуска приложений, SaaS — готовое программное обеспечение как сервис.
7. **Что такое CI/CD?** CI — Continuous Integration, непрерывная интеграция. CD — Continuous Delivery или Continuous Deployment, непрерывная доставка или развертывание.
8. **Что такое Pipeline?** Pipeline — автоматическая последовательность шагов, например получение кода, установка зависимостей, сборка, тестирование и развертывание.
9. **Image и Container?** Image — шаблон для запуска приложения. Container — работающий экземпляр этого образа.
10. **Что значит `-p 5000:5000`?** Первый порт — порт компьютера или сервера, второй — порт внутри контейнера. Проброс нужен, чтобы к приложению внутри контейнера можно было обратиться снаружи.

## Команды для выполнения практики

```bash
git init
git add .
git commit -m "initial commit"
# внесите небольшое изменение в app.py
git add .
git commit -m "add app"
# обновите README.md
git add .
git commit -m "update README"

git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/devops-mini-project.git
git push -u origin main

docker build -t devops-app .
docker run -p 5000:5000 devops-app
```

После добавления `.github/workflows/ci.yml`:

```bash
git add .
git commit -m "add CI pipeline"
git push
```

Проверка:

```bash
git log --oneline
docker ps
```

В браузере: `http://localhost:5000`.
